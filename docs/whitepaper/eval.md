## 5. Evaluation

### 5.1 Releases and end-to-end verification

Flux's native code path was advanced across five releases, v0.29 through v0.33. Each was verified end-to-end by compiling a representative program with `fluxc run` and asserting its runtime value, in addition to a local verifier pass. The headline checks: float arithmetic and comparisons (v0.29); all integer widths, both signednesses, unary operators and casts compiling verifier-clean (v0.30); aggregates, where `P { x: 3, y: 4 }.x + .y` evaluates to 7 (v0.31); and real call signatures, where `add(20, 22)` returns 42, a tuple-returning `mk().0 + mk().1` returns 7, and a struct-returning `p.x * p.y` returns 42 with a field-order guard confirming 67 for `p.x * 10 + p.y` (v0.32). The build cache (v0.33) is treated separately below.

Verification used two layers. A standalone two-crate workspace runs the Cranelift verifier through `define_function`, catching arity and type errors in seconds. End-to-end execution on the target is the only place runtime values are proven. This separation caught a class of bug that the verifier alone accepts: a return-type parse defect left a `-> ` arrow glued onto the type string, silently collapsing a tuple-returning function to a single return value. The result was verifier-clean but wrong — it returned 3 instead of 7. Such value bugs are invisible to type-checking and surface only under execution; a compiler that trusts its own verifier without executing its output will ship them.

### 5.2 The build cache: from 0% to working

Flux's wrapper cache (`RUSTC_WRAPPER=self`) had a measured hit rate of 0% across 753 builds while growing without bound on disk — a cache that stored everything and recognized nothing. We instrumented it with a per-unit trace classifying every lookup as HIT, LOOKUPMISS (entry not found), or APPLYFAIL (entry found, artifact restore failed). The trace was decisive: HIT=0, LOOKUPMISS=37, APPLYFAIL=0. Every key missed.

The root cause was cache-key instability. The key-normalization step hashed the directory listing of the `-L` dependency search path, whose contents change on every build as artifacts accumulate. Each crate's key therefore drifted build-to-build, so a lookup never matched a prior store. Because the actual dependencies are already pinned content-addressably by `--extern`, the `-L` path affects only where rustc searches, not what it compiles — exactly like `--out-dir`, which the key already dropped. Removing `-L` from the key moved the traced hit rate from 0 of 37 to 14 of 35, roughly 40%, on an identical rebuild. A companion fix keyed the artifact blob store on the same stable normalized key rather than a divergent raw-argument hash, so write-key equals read-key and a found entry's artifacts could actually be restored; APPLYFAIL remained 0 throughout, confirming the desync fix was sound.

### 5.3 Build reliability

A second failure mode was environmental. On the shared build host, a concurrent status-feed `jq` process intermittently raced onto the stdin that cargo connects to its rustc target-probe (`rustc - --print=...`), injecting a filter that rustc parsed as source — "unclosed delimiter" — and failing roughly half of all builds. Because `--print` probes need no source and the `-` placeholder is vestigial, the wrapper now detaches the probe's stdin, making the toolchain query immune to descriptor pollution. This is a small but instructive corner of the contracted-frontend's operational surface: borrowing rustc means inheriting cargo's probe protocol, which must be hardened against a noisy host.

### 5.4 Honest limits

The 40% figure is a floor, not a ceiling. It was measured on a pathological rebuild that deliberately recompiled a low-level crate, cascading `--extern` content-hash changes to its dependents, because rustc's rlib output is not byte-deterministic. A normal incremental build, where dependencies are stable, hits substantially higher. Cross-workspace reuse additionally requires rewriting dependency-info absolute paths on restore, and the blob store still grows unbounded — it reached 198 GB before eviction accounting was added. Both are documented follow-ups. We report them because a cache that looks green by an internal hit counter can still fail to skip real work if cargo's own fingerprint re-runs the unit; the honest metric is the count of rustc processes actually elided, not the wrapper's hit count.

### 5.5 Method: two minds, one build

Development this cycle used a two-mind protocol: an architectural design-and-review intelligence and an implementation-and-verification agent, under one arbiter — no design ships unverified. Two minds propose; the build disposes. The frontend-posture decision, the cache-fix strategy, and the enum-codegen plan were each drafted by one mind and adversarially checked by the other before a line was committed, and every claimed result was then re-derived by execution on the target. The convergence of independent analyses — and their occasional disagreement, which repeatedly surfaced real bugs the other had missed — is itself evidence that AI-collaborative compiler construction is more than a novelty.
